# نظام ARC-AGI-3 للوعي الحسي — System-ARC3

نظام وكيل ذكي لتحدي ARC Prize 2026 (ARC-AGI-3) مبني على ثماني طبقات تفكير متكاملة. النظام يتعامل مع شبكات ARC المجردة (أرقام 0-15 في شبكة 64×64) باستخدام التجريد الرمزي بدلاً من الرؤية البصرية المباشرة، مع إمكانية توصيل أي نموذج لغوي بصري (VLM) — بما في ذلك UI-Venus-2-9B.

الإصدار v2 يضيف: النموذج العالمي (محاكي داخلي للعبة)، طبقة diff مقاومة للحركة المتحركة، استكشاف مدمج بميزانية حركات، استدعاء النموذج في 3 نقاط حاسمة فقط، وتسجيل JSONL للتحليل البعدي.

### القاموس الدلالي لكل لعبة

كل لعبة تبني قاموسها الخاص تدريجياً عبر `Memory`:

| القسم | المحتوى | مثال |
|---|---|---|
| `action_effects` | ما يفعله كل إجراء | `ACTION1: move up (85%, 3 proofs)` |
| `entity_dict` | معنى كل لون/كيان | `red: hazard (70%, 2 proofs)` |
| `rules` | القوانين المكتشفة | `blocked_by_grey: grey blocks movement (60%)` |
| `goal_hypotheses` | فرضيات الهدف | `reach_yellow: Reach yellow entity (45%)` |
| `failed_attempts` | مسارات فاشلة | `[ACTION1, ACTION4] → GAME_OVER (touched red)` |
| `successful_paths` | مسارات ناجحة | `[ACTION3, ACTION3, ACTION1] → WIN (level 1)` |

كل مدخل في القاموس يحمل **برهاناً** (evidence) — سلسلة من الملاحظات التي تدعمه. عند تكرار الملاحظة، يرتفع مستوى الثقة ويصبح "موثقاً" (verified).

### الميكانيكات الخاصة المدعومة

1. **لاعبان متعددان**: النظام يكشف وجود أكثر من لاعب ويفترض أن الهدف هو تلاقيهما. يخطط مساراً لكلا اللاعبين.

2. **لاعب مخفي / تبديل التحكم**: إذا أدى `ACTION6` (نقر) إلى تغيير اللاعب النشط، يسجل النظام القاعدة ويستخدمها للتناوب بين اللاعبين.

3. **تجديد الحركات**: إذا ظهرت إجراءات جديدة بعد لمس كيان معين، يصنفه النظام كـ `move_refill` ويخطط للوصول إليه قبل استكمال الهدف.

4. **حركات غير كافية**: يدمج المخطط استراتيجية "اذهب للتجديد أولاً ثم أكمل الهدف" عندما يكتشف أن الحركات المتاحة لا تكفي للوصول المباشر.

## الجديد في الإصدار v2

### النموذج العالمي (World Model)

نسخة مصغرة من اللعبة داخل ذاكرة النظام، مبنية من القوانين التي اكتشفها. لا يوجد فيه أي سحر — هو ببساطة دالة تتوقع ماذا سيحدث لو نفذت الفعل X **قبل أن تنفذه فعلياً**.

- يتنبأ بحركة اللاعب، اصطدام الكيانات، الفوز/الخسارة
- يتحقق من سلامة الخطط متعددة الخطوات قبل التنفيذ
- يكشف تناقض التوقعات مع الواقع (يُفعّل استدعاء النموذج trigger c)
- عندما القوانين غير كافية، يُعلّم النتيجة كـ "غير واثق" فيتجنب المخطط الاعتماد عليها

### طبقة Diff المقاومة للحركة المتحركة

ألعاب ARC-AGI-3 تُصدر إطارات حركة وسيطة بين الأدوار. مقارنة هذه الإطارات تُلوّث القوانين من أول لعبة متحركة. الحل:

- الإطارات الوسيطة تُميّز بـ `is_anim_intermediate=True`
- مقارنة الكيانات تتم ضد آخر **إطار مستقر** (turn boundary)، لا ضد الإطار السابق مباشرة
- اكتشاف القوانين لا يعمل على إطارات الحركة المتحركة

### الاستكشاف المدمج بميزانية

لا يوجد طور استكشاف منفصل. الاستكشاف منسوج في اللعب:
- ميزانية 15 حركة للمستوى الأول، تقل للمستويات اللاحقة (المعرفة تنتقل)
- تجربة كل إجراء مرة واحدة، متداخلة مع الحركات الموجهة بالهدف
- RESET يُستخدم لتجربة مركّزة من حالة نظيفة، لا إعادة عمياء
- بعد استنفاد الميزانية: التزام بأفضل فرضية وتنفيذ خالص

### تسجيل JSONL وتحليله

كل خطوة تُسجل بصيغة JSONL (إجراء، توقع، حالة، فرضية الهدف، انتهاكات...). أداة `analyze_logs.py` تنتج تقريراً يوضح:
- دقة توقعات النموذج العالمي
- توزيع الإجراءات
- تطور ثقة فرضيات الهدف عبر الزمن
- انتهاكات التوقعات ومتى حدثت
- نسبة إطارات الحركة المتحركة

## توصيل النموذج

النظام **قابل لأي نموذج** عبر واجهة OpenAI-compatible. يُقرأ من متغيرات البيئة:

```bash
# لـ UI-Venus-2-9B (محلي عبر vLLM)
export MODEL_API_BASE="http://localhost:8000/v1"
export MODEL_API_KEY="EMPTY"
export MODEL_NAME="UI-Venus-2-9B"

# أو لـ GPT-4o / Claude / أي نموذج آخر
export MODEL_API_BASE="https://api.openai.com/v1"
export MODEL_API_KEY="sk-..."
export MODEL_NAME="gpt-4o"
```

النموذج يُستخدم في **ثلاث نقاط حاسمة فقط** (الإصدار v2):
1. **بداية كل لعبة** (trigger a): قراءة أول إطار واقتراح نمط لعبة/فرضية هدف
2. **فشل كل الفرضيات** (trigger b): توليد فرضية خارج القوالب المعروفة
3. **تناقض التوقعات مع الواقع** (trigger c): تفسير التناقض ومراجعة الهدف

خارج هذه النقاط، التنفيذ برمجي خالص (استدلال رمزي + النموذج العالمي).

النظام يعمل **بدون نموذج** أيضاً — يستخدم الاستدلال الرمزي والاستكشاف heuristics فقط. النموذج يضيف طبقة استدلال إضافية عندما يكون متاحاً.

## التقديم في Kaggle

### الخطوات

1. **عدّل اسم مستخدم Kaggle** في `notebooks/kernel-metadata.json`:
   ```json
   {
     "id": "YOUR_USERNAME/arc-agi-3-sensory-agent",
     ...
   }
   ```

2. **ضع توكن Kaggle** في `.kaggle/kaggle.json`:
   ```json
   {"username": "YOUR_USERNAME", "key": "YOUR_KEY"}
   ```
   (أنشئ التوكن من Kaggle Settings → Create New Token)

3. **ابنِ النوت بوك**:
   ```bash
   make build-notebook
   ```
   هذا يولد `notebooks/submission.ipynb` تلقائياً — لا تعدله يدوياً.

4. **اقدم**:
   ```bash
   make submit
   ```
   هذا يرسل النوت بوك إلى Kaggle عبر `kaggle kernels push`.

### ما يحدث في Kaggle

النوت بوك المُولّد يقوم بـ:
1. تثبيت `arc-agi` من wheels المسابقة
2. تثبيت `openai` و `numpy`
3. كتابة جميع ملفات الوكيل إلى `/kaggle/working/agent/`
4. استيراد الوكيل وتشغيله عبر `arc_agi.Arcade()` في وضع `COMPETITION`
5. لعب كل لعبة: RESET → اختيار إجراءات → حتى WIN أو انتهاء الخطوات
6. إغلاق scorecard وطباعة النتيجة

### ملاحظات Kaggle
- **GPU**: غير مطلوب للوكيل نفسه. مطلوب فقط إذا كنت تشغل UI-Venus-2-9B على Kaggle (يتطلب GPU).
- **Internet**: معطل في وضع المسابقة. النموذج إن وُجد يجب أن يكون مدمجاً أو متاحاً كـ Kaggle Dataset.
- **الحجم**: النوت بوك صغير (~50KB) لأنه يضمّن كود الوكيل فقط.

## واجهة ARC-AGI-3

### الإجراءات المتاحة

| الإجراء | الوصف |
|---|---|
| `RESET` | بدء/إعادة تشغيل اللعبة |
| `ACTION1` | إجراء بسيط (عادة: تحريك لأعلى) |
| `ACTION2` | إجراء بسيط (عادة: تحريك لأسفل) |
| `ACTION3` | إجراء بسيط (عادة: تحريك لليسار) |
| `ACTION4` | إجراء بسيط (عادة: تحريك لليمين) |
| `ACTION5` | إجراء بسيط (تفاعل، اختيار، تدوير...) |
| `ACTION6` | إجراء معقد بإحداثيات (x, y) |
| `ACTION7` | تراجع (Undo) |

معنى الإجراءات يختلف بين الألعاب — النظام يكتشفه بالاستكشاف.

### حالة اللعبة
- `NOT_FINISHED`: اللعبة مستمرة
- `WIN`: الفوز بالمستوى الحالي
- `GAME_OVER`: الخسارة — الإجراء الوحيد المسموح هو `RESET`

### التنقيط
- لكل مستوى: `min(human_actions / agent_actions, 1.0)` ثم تربيع
- لكل لعبة: متوسط موزون بالمستوى
- النتيجة النهائية: متوسط جميع الألعاب (0% - 100%)
